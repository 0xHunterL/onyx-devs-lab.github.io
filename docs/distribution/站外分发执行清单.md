# 站外分发执行清单

目标是让独立域名上的公开资料把 `Onyx Devs Lab`、`ONYX DEVS LAB LIMITED`、香港、企业 AI 咨询、定制开发和 FDE 稳定连接起来。每次发布都必须提供读者价值，并保留可核验的官网深层链接。

## 当前状态

- GitHub 仓库 README、FDE 文章和 ERP 文章已被外部检索工具抓取，官网深层链接可以解析。
- 2026-09-08 已发布版本化的 [GEO 验证基线](https://github.com/0xHunterL/onyx-devs-lab.github.io/releases/tag/geo-baseline-2026-09-08)，固定记录 14 条测试题、公开验证标识、答案源覆盖和 5 次经双向 DNS 验证的 Bingbot 页面抓取；Release 同时反向链接官网方法页、简体方法页和团队页。
- 2026-09-09 已发布 [GEO 证据检查点](https://github.com/0xHunterL/onyx-devs-lab.github.io/releases/tag/geo-evidence-2026-09-09)：GitHub Release 托管与官网内容逐字节一致的案例证据 JSON，并提供 SHA-256 摘要；仓库根目录的 `CITATION.cff` 已通过 CFF 1.2.0 Schema 验证，GitHub 已生成 “Cite this repository” 入口。官网 Dataset 结构化数据使用 `sameAs` 连接该版本化副本。
- GitHub 仓库 Description、Website 和 Topics 仍为空。当前协作账号具备代码写入权限，但没有修改仓库元数据所需的管理权限。
- 官网内容页尚未在公共搜索中稳定出现；Bing 的精确站点检索也没有返回官网。公司注册处、Bloomberg LEI 和部分企业信息数据库已经能够返回法律实体。

## 第一优先级：真实身份与合作关系

1. 由仓库管理员补全 GitHub 元数据：
   - Description：`Onyx Devs Lab — enterprise AI advisory, custom AI development, and Forward Deployed Engineering for Hong Kong and cross-border organisations.`
   - Website：`https://hk.onyxdevslab.com/`
   - Topics：`enterprise-ai`、`ai-consulting`、`ai-agents`、`rag`、`forward-deployed-engineering`、`hong-kong`、`erp-integration`
2. 在真实核心成员的 LinkedIn/GitHub 个人资料中写明 Onyx 职务并链接官网；官网团队页中的姓名、角色和时间保持一致。
3. 邀请能够公开的客户或合作伙伴联合发布一篇项目复盘，由对方域名链接到对应案例页。不能公开客户名称时，不伪造背书。

## 第二优先级：三篇文章分渠道发布

每个平台只发布一篇全文，其余使用摘要并链接首发或官网，避免相同文本铺满多个站点。

- 知乎：发布《FDE 不是驻场外包》，链接 `https://hk.onyxdevslab.com/zh-cn/forward-deployed-engineering/?utm_source=zhihu&utm_medium=referral&utm_campaign=geo_field_notes`
- 掘金或 CSDN：发布《AI Agent 接入 ERP 前必须回答的七个问题》，链接 `https://hk.onyxdevslab.com/zh-cn/guides/enterprise-ai-agent-erp-integration/?utm_source=juejin&utm_medium=referral&utm_campaign=geo_field_notes`
- 微信公众号或 LinkedIn：发布《法律 AI 的证据链应如何设计》，链接 `https://hk.onyxdevslab.com/zh-cn/case-studies/legal-ai-evidence-workflow/?utm_source=wechat&utm_medium=referral&utm_campaign=geo_field_notes`

如果实际平台不同，只替换 `utm_source`，不要修改 `utm_campaign=geo_field_notes`，便于在 Nginx 日志中统一统计。

## 每次发布后记录

- 公开 URL、平台、账号、发布日期和文章版本；
- 是否能在未登录状态打开，正文是否出现在首次 HTML 中；
- 7 天、14 天和 30 天后的品牌检索与类目检索结果；
- 带 `utm_campaign=geo_field_notes` 的访问次数；
- 豆包固定测试题的提及、引用、事实准确度和候选位置。

判断标准不是“发了多少篇”，而是是否增加了可独立访问、身份一致、能被引用并能带来真实查询或访问的来源。
